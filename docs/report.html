Timestamp precision and checksum policy

The small endian/precision fixtures contain a query and response 789 ns apart. Nanosecond PCAP preserves the interval. Microsecond PCAP stores both at the same timestamp, so the strict-prior matching rule declines to infer order.

IPv4 UDP checksum rules

Zero on the wire means no checksum was supplied. A nonzero checksum is verified over the IPv4 pseudoheader and declared UDP datagram, padding odd length only for arithmetic.

A calculated checksum of zero is transmitted as 0xffff. The parser tests both cases independently.

Declared lengths

UDP bytes beyond the declared UDP length and Ethernet padding beyond the IPv4 total length are counted separately, never fed into DNS.

record offset + 16 = first packet byte
integer seconds × 10⁹ + fraction = timestamp ns

Validation and scope

Independent byte checks

Literal Ethernet/IPv4/UDP and compressed-DNS vectors, independent checksum arithmetic, all four PCAP magic variants, odd-length UDP, encoded-zero checksum, pointer loops/bounds, 500 seeded mutations, exact correlation boundaries and full artifact reconciliation.

Bounded subset

4 MiB per file, 4,096 records, 65,535 captured bytes per packet, 4,096 DNS bytes, 32 resource records and 32 compression pointers per name. Expanded names cannot exceed 255 bytes. Unknown DNS RDATA is length-checked and counted as opaque.

Outside scope

PCAPNG, VLANs, IPv6, TCP, IP reassembly/options, nonstandard PCAP metadata, DNSSEC validation, EDNS semantics, name resolution and live traffic.

Five warmed parse-and-analysis timings per fixture are preserved. The tiny study makes no production parser, IDS or throughput claim.
